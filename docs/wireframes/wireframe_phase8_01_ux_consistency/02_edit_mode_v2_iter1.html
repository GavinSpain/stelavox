Edit Mode v2 — what's different
1
Mode tab bar promoted. Edit / Director / Focus sit in a compact toggle group inside the header. The Director tab carries a saturated pulsing dot when the Director has activity — visible peripherally without dominating. (Currently a tiny grey orb at 7px; new tab badge is 6px but pulsing + saturated.)
2
Layer column header. Five lane labels — Book / Acts / Chapters / Scenes / Beats — each in its own per-layer tone. Acts as a permanent legend at the top of the tree, so the eye always has a map for "what level is this." The colour each label uses is the same tone the layer's type-icon uses below.
3
Per-layer type icons + typography. Book = ◈ in verdigris-bright box. Act = I / II / III roman numerals in sea-glass box. Chapter = 1 / 2 / 3 in slate box. Scene = § in dusk box. Beat = ▪ in muted text-secondary. Row heights step down (38 → 34 → 32 → 30 → 28px) and typography goes from Inter 600 15px at the book level to Inter 300 12.5px at the beat level. You can identify any row's type from peripheral vision.
4
Word-count column. Per-row at-a-glance "where am I" indicator. Mini bar + actual/target numbers. Green when complete, amber when over target, muted when under. Aggregates upward (chapter row shows total of its scenes' words; act shows total of its chapters'). This is the single most useful piece of information a writer reads while navigating the tree.
5
Lifecycle pills + status pips. Pills are saturated, bordered, easy-read-at-distance: Running / Review / Complete / Queued / New. Pip alone for "settled" beats (just a coloured dot). Pulsing pips for in-motion states (running). Calmer styling for completed beats — the eye is drawn to the rows that need attention, not to a uniform field of "everything is the same."
6
Filter chips as a placeholder. "All / Incomplete / Pending review / Running" chips with counts, plus a "Find a node ⌘F" search box. Visually present but tagged with a dashed callout-yellow "Filtering — 8.03" banner so we don't accidentally ship the visual without the function. This is the slot the filtering work lands into.
7
Bottom-right status indicator (AppShellStatusIndicator). Currently invisible in the production app. Here it's a small floating chip with a pulsing pip + Director status + ETA. Always visible, no matter the mode, so the writer always knows the Director's heartbeat.

03 — Writer's eye · navigating Shadow Protocol
"I'm scanning the tree to find what's running, what's done, and where I should write next"

A writer in mid-project doesn't look at the tree to admire its structure. They look at it for three things, in order: where am I right now, what's the Director up to, and what needs my attention. Every visual choice should serve those three reads. Let me check the iter1 against that.

What this version solves

The per-layer type icons + typography hierarchy means I no longer count indentation. "◈ Shadow Protocol" is the book, "I Act One" is an act, "1 Salvage" is a chapter, "§ The Iron Ghost" is a scene, "▪ The Signal" is a beat. The eye recognises the row's type before it reads the name. This is the single biggest fix for "I can't tell what's what."

The word-count column gives me at-a-glance progress without clicking anything. The lifecycle pills make "what's running / what needs review" jump off the page. The pulsing dot in the bottom-right corner means I know the Director is alive even if I'm three scrolls deep.

What I'd push or rethink
T-1
The type icons are doing real work but they may be too dense. Five distinct glyphs (◈ / I / 1 / § / ▪) in five distinct colours is information-rich, and the eye can learn them fast. But on a 200-row tree it could start to feel decorated. Counter-proposal worth wireframing: keep only 2–3 layer markers and rely on typography for the rest. E.g., Book + Act get icons, the rest get typography only. Open question — I lean toward keeping all five for the legibility win, but worth a side-by-side.
T-2
Word-count column at every layer is great, but the unit is mixed. Book/Act/Chapter show a progress bar with "X/Y" format; Scene shows just "Xw" with no bar; Beat shows "X/Y" again but is over/under-coloured. Inconsistent. Recommend: progress bar everywhere where there's a target, plain word count only when there isn't. Scene level should aggregate beats' targets if any exist.
T-3
The lifecycle pill "3 running" on a parent (Chapter / Scene) row tells me how many descendants are running. That's powerful but undocumented. The number should be a count of running descendants. If the writer clicks the pill, the tree could filter to just those rows. Out of scope for 8.01 visual pass — flag for 8.03 (filtering) wireframe.
T-4
Indent guides (faint vertical lines) are subtle and barely visible. I drafted them in but the CSS rgba is at 0.18 which is essentially invisible. Bump to 0.32 or so, especially for the lines that connect actively-expanded sub-trees. Could also tint them with the layer colour at the indent position (subtle but coherent).
T-5
The detail panel on the right shows Act One's "Author's note" but no actual prose. Acts/Chapters/Scenes are structural — they have summaries but no leaf prose. The detail panel for non-leaf nodes should look different from the detail panel for leaf nodes (beats). For an Act, we want a "child overview" — a sub-tree summary, maybe a sparkline of word-count over the descendant chapters. For a Beat, we want the ProseEditor canvas. Iter2 of this wireframe should design both layouts side-by-side.
T-6
No "next likely action" affordance per row. Hover state should reveal a few quick actions: Expand · Refine · Synthesise · Comment · Lock. Currently the user has to open the detail panel to access these. Recommend a hover-revealed action strip on the right of the row, tucked behind the lifecycle pill until hover. Same pattern as Linear's "actions on hover."
T-7
Scrolling 114 nodes is a real concern. Even with the per-layer cues, scrolling past 50+ rows to find "Chapter 7 Scene 3 Beat 5" is tedious. The filter chips help (filter by status), but ultimately the writer wants collapse-all-except-current-path, jump-to-next-incomplete, and fold-completed-by-default. These are 8.03 functional concerns but the visual affordances should be designed now.
T-8
iPad consideration (F-8 carryover). At 1024px width (iPad landscape), sidebar 220 + detail 480 leaves 324px for the tree. Beat rows are 118px indent + ~150px name + 60px word count + 120px status = 448px minimum. Doesn't fit. Either the detail panel collapses to a slide-over on iPad, or the tree gets a "compact mode" with smaller indents. Recommend slide-over: tap a node, detail panel slides in from the right, takes 80% of the width, can be dismissed.
Honest gut feel

The single biggest "click" moment for me looking at this is the layer column header at the top of the tree. The first time you see the tree, your eye reads "Book / Acts / Chapters / Scenes / Beats" at the top, then drops to the rows below and immediately understands the indentation structure. The type icons reinforce that learning. After that, the lifecycle pills do the daily work of "what should I look at." This feels meaningfully better than the current implementation. The biggest unsolved items are T-5 (detail panel for non-leaf nodes) and T-8 (iPad). Everything else is iteration.

04 — Decisions iter1
Decisions baked in
Type icons + typography
Per-layer treatment: ◈ Book / I·II·III Act / 1·2·3 Chapter / § Scene / ▪ Beat. Sizes step from 22px → 14px box. Typography from Inter 600 15px (book) → Inter 300 12.5px (beat). Layer colours: --layer-book through --layer-beat.
Layer column header
Always-present row above the tree showing Book / Acts / Chapters / Scenes / Beats labels in their respective layer tones. Acts as a legend.
Word-count column
Per-row mini progress bar + actual/target number. Green when complete, amber over, muted under. Aggregates upward. T-2 open: unit consistency across layers.
Lifecycle pills
Saturated bordered pills for "in motion" or "needs attention": Running / Review / Queued / New / Complete. Pip-only for settled beats.
Filter row
Placeholder visual with active chip count. Functional in 8.03. Yellow dashed banner so the visual doesn't ship without the function.
AppShell status
Bottom-right pill, always visible across all modes. Pulsing pip + Director status + ETA. NEW verdigris use candidate (status pip).
Mode tab Director dot
6px saturated pulsing pip on the Director tab when there's activity. Currently a static 7px grey dot.
Open · T-* recommendations
T-1 icon density
All 5 layers carry icons vs. icons only on book+act. I lean keep-all-5 — once-learned never-forgotten.
T-2 word-count unit
Progress bar everywhere a target exists; plain word count only when none. Recommend.
T-3 parent-pill click→filter
Click "3 running" on a parent row → filter tree to those 3 descendants. Defer to 8.03 filtering.
T-4 indent guides
Bump opacity 0.18 → 0.32; tint with layer colour at the indent position.
T-5 detail pane per node type
Important. Acts/Chapters/Scenes (non-leaf) get a "child overview" detail layout — sub-tree summary, sparkline, key metadata. Beats (leaf) get the ProseEditor canvas. Wireframe both in iter2 of Edit Mode.
T-6 hover action strip
Per-row hover-revealed quick actions: Expand / Refine / Synthesise / Comment / Lock. Right-aligned, hidden behind lifecycle pill until hover.
T-7 tree navigation
Collapse-all-except-path, jump-to-next-incomplete, fold-completed-by-default. Defer functional to 8.03; visual affordances to iter2.
T-8 iPad responsive
At 1024px viewport, detail panel becomes slide-over (taps in from right, ~80% width, dismissible). Tree's indent calibration unchanged but pane competes only when invoked.
Dashboard items carried forward (will fold into 01_dashboard_v2_iter4)
Top organisation
Echo + next-line + stats band currently stacked → competing for top of page. Try merging echo + next-line, moving stats to the right of echo, OR pushing stats below the doc card.
F-1 sample shape
Sample novel sits in a dedicated sample-author@stelavox.platform account, copied into user's space on request only (not auto-installed). Admin-swappable. Shadow Protocol stands in until a small purpose-built sample is authored.
F-4 "Get started" reframe
First-time primary CTA renamed "Get started" — leads to main authenticated app where user creates first project inline (no separate modal wizard).
F-6 empty sidebar
Faded "PROJECTS" section header + small "+ Add project" affordance + italic line "Your novels and papers will live here."
F-7 "Yours."
Fourth tile in philosophy strip — "IV. Yours." with body "Your prose stays yours. We don't train on your work."
F-8 vertical compression
Compress hero so philosophy strip is in-view at 720px laptop / 768px iPad. iPad is now a target form factor.
