02 — Annotations
1
Progressive Disclosure — Tab Only Appears With Content
Brand Identity §10.2 · Component Spec §5.2
The Agent tab is hidden until the node has content — specifically, until the summary field is non-empty. An empty node has no meaningful context to send to an agent. The tab appears (via opacity transition, --duration-fast) when the author saves their first summary. For leaf nodes: the Synthesise operation is only shown when the summary is non-empty.
2
Operation Types per Node Type
Product Spec §11 · Agent Profile Library v0.3
Available operations are determined by the node's layer_type. Non-leaf nodes (book, act, chapter, scene): Expand · Refine · Critique. Leaf nodes (beat, paragraph_group): Synthesise · Refine · Critique. All nodes: Custom (always available, opens instruction-only mode with no preset profile). Operations are rendered as selectable pills — only one can be active at a time.
3
Agent Profile Selector
Product Spec §11 · UI Design §6.2
Shows the default profile for the selected operation on this node type. Clicking opens a dropdown listing all compatible profiles for this operation type. Each profile shows its name, operation type icon, and model tag. BYOK users see their configured model. Platform users see the platform model. The author can override per operation but the default is applied automatically based on default_agent_profile_id on the layer definition.
4
Context Node Selection — Auto-Selected, Author Can Override
Product Spec §10 · §11.4
The system auto-selects context nodes based on the agent profile's context_rules. The author sees the selection and can uncheck nodes they do not want included. Checkboxes are the only interaction — the author cannot add context nodes from here (that is done in the Context tab). The count label shows how many were auto-selected. On hover of any item, a tooltip shows the context node's full description.
5
Running State — Header Bar Replaces Operation Form
UI Design §5.4
When an operation starts, the operation form collapses to a summary row (non-interactive). The running header bar slides down from the tab strip border. The Stop button sends a cancellation signal — the operation halts, partial output is discarded, the agent_job is marked cancelled. The streaming output area appears below the summary row and grows as text arrives. The token tracker updates in real time from the streaming response's token count events.
6
Streaming Output Renders in Lora — The Only Exception in Structural Panels
Brand Identity §5.4 · Component Spec §5.4
The streaming prose output renders in Lora 400, 14px, line-height 1.85. This is the only place Lora appears outside the ProseEditor and FocusMode components. The rationale: the agent is generating manuscript text. The typeface signal applies to the output regardless of which surface it appears on. The streaming cursor uses --color-agent-running (blue, not verdigris) — it is the agent writing, not the author. The label "Live Output" carries the italic tag "← rendered in Lora (manuscript)".
7
Token Tracker — Real-Time Feedback
Product Spec §11.5 · §5.3
Shown during execution. Input token count is calculated before the operation starts (from context assembly) and displayed immediately. Output token count increments in real time as the stream arrives. Both are Inter 300 10px --color-text-muted. For Platform tier users this shows consumption against their token budget (shown as % of budget in account settings). For BYOK users this informs their own API provider bill. Updated from streaming events — Anthropic's API returns token counts in the final stream event; interim counts can be estimated from character count.
8
Complete State — Result Requires Author Decision
Brand Identity §1.2 — Author is the origin
The result is never auto-accepted. It is presented for the author's review. Three actions: Accept (replaces prose field, previous version auto-saved to History), Append to existing (adds result below any existing prose — useful for building up a beat in multiple passes), Regenerate (runs the same operation again with the same settings, produces a new result). The warning note — "Accepting will replace the current prose field. Previous version saved to History automatically." — is the brand voice: direct, complete, no alarm.
9
Result Text in Lora — Same Rule as Streaming
Brand Identity §5.4
The completed result prose renders in Lora 400 14px, same as streaming. Same rationale: this is manuscript text regardless of the panel it occupies. The result area has a slightly stronger border (--color-border-default) than the streaming area (--color-border-subtle) to signal that this is a completed artefact rather than live output. The border-left is not verdigris — the result is not yet in the prose field, it has not been accepted, so it does not carry the accent.
10
Accept Button — Verdigris, Sanctioned Category 3
Brand Identity §4.4 Category 3 — Completion
The Accept button uses --color-accent (verdigris) as its background. This is a deliberate extension of the sanctioned uses: accepting the result is an act of completion — the agent's output becomes the author's prose. The verdigris signals this moment of commitment. This is an eighth sanctioned use of verdigris in the Category 3 (Completion) group. Update Brand Identity §4.4 and Component Spec §1.4 to include this use. The Regenerate button explicitly does not use verdigris — it is not completion, it is a retry.
11
Expand Operation — Generates Child Nodes
Product Spec §11.3 · §9.4
The Expand operation is only available on non-leaf nodes. It generates child nodes in the tree below the current node — for a chapter, it generates scenes; for a scene, it generates beats. The "Target node count" field is a hint to the agent, not an instruction — the profile's system prompt uses it as guidance. The result of an Expand operation is not prose but new tree nodes with summaries. These appear in the tree immediately (optimistic UI) and are confirmed when the API response is saved to the database.
12
Job History — Current Version Highlighted
Product Spec §14 · UI Design §5.2
The history view shows all agent_jobs for this node, most recent first. The current (accepted) version is highlighted with a verdigris border — it is the completion in the prose field. Previous versions can be restored individually. The history list is the same data as the History tab — the Agent tab shows jobs only; the History tab shows all changes including manual edits. A failed job is shown with a red border and no restore option. Job metadata includes: operation type, profile name, model, token counts, timestamp.
13
Restore — Replaces Current Prose, Saves to History
Product Spec §14.3
The "Restore this version" button replaces the current prose field with the historical version. The current prose is automatically saved to History before the restore — nothing is ever permanently lost. No confirmation dialog is required (the restoration is reversible). After restoration, the restored job moves to the top of the history list as the "current" version, highlighted with a verdigris border. The toast reads: "Version restored. Previous prose saved to history." (brand voice: specific, no alarm).

⚠ Verdigris Usage Update — New Sanctioned Use Identified
The Accept button background (--color-accent) is an eighth sanctioned use of verdigris. Category 3 — Completion: accepting the agent's result is the act of completion, the moment the generated prose enters the author's manuscript. This is the same category as the approved status badge and the word count at target. Update Brand Identity v1.1 §4.4 (add to Category 3 list) and Component Spec v1.0 §1.4 (add to the seven-location table). The total is now eight sanctioned uses.
