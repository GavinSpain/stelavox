Mode Panel Chrome — Edit · Director · Scheduler · v1.0
2026-06-10
Goal

The three right-slot mode panels (Edit / Director / Scheduler) currently fight each other on structural chrome — surface, header strip, title scale, padding, container width — even though they live in the same slot and serve the same architectural role. This wireframe locks a shared panel chrome that all three adopt, while preserving the divergences each mode has earned (Director's brand mark, Scheduler's section labels).

Decisions Locked
D1 — Shared surface. All three mode panels render on --color-bg-surface, fill the slot height, scroll internally. Scheduler stops being transparent over the page background.
D2 — Shared header strip. Every mode panel has a header band: title row + meta row, padded 14px 20px, ending in a 1px solid --color-border-subtle bottom border. The band is non-scrolling chrome; content scrolls beneath.
D3 — Shared title scale. Inter 18px / 600 for Edit and Scheduler. Director keeps its brand-mark + Cinzel "DIRECTOR" wordmark (Inviolable #4 v2.5 — earned divergence; brand-mark category).
D4 — Drop centering on Scheduler. maxWidth: 980; margin: 0 auto removed. The queue + jobs lists fill the slot like Director's conversation does.
D5 — Drop ✕ on Director header. Mode-as-URL refactor made the ✕ redundant against the ModeTabBar's Edit tab. Stop / Clear conversation / History stay — those are mode-specific verbs that the tab bar doesn't carry.
D6 — Section labels stay Scheduler-only. Uppercase 10px / letter-spacing .35em ("ACTIVE BRIEF" / "QUEUED BRIEFS" / "AGENT JOBS") is the right visual vocabulary for grouped lists; Edit and Director don't have grouped-list content.
D7 — Verdigris count unchanged. Nothing in this polish adds a new use of --color-accent. Inviolable #2 stays at 12 uses; new uses still require the §5.3 three-test gate.
D8 — Layout primitive deferred. A shared <PanelHeader> React primitive (title row + meta row + bottom-border container) is a follow-up after D1–D6 land. The first pass restyles in place to keep the diff minimal and reversible.

Annotations
1
Edit before — no header border. The header band today bleeds into the TabStrip. Visually OK because the TabStrip's own bottom-border carries the rhythm, but it's also the only one of three panels without an explicit header/content separator. Inconsistent in a polish that's defining the convention.
2
Edit after — header band gets 1px --color-border-subtle bottom border. Zero functional change for Edit; just brings the visual rhythm into line with Director + Scheduler. The TabStrip below loses its own border-top to avoid doubling. (If TabStrip is read as "another header layer", we can drop its own bottom-border instead — either single-line option works; I'd default to keeping TabStrip's bottom-border since that's what's drawn today.)
3
Director before — ✕ close button. Pre-mode-as-URL refactor, ✕ navigated back to "no panel mounted." Post-refactor it navigates to /edit, which is exactly what clicking the Edit tab in ModeTabBar does — and the tab is more discoverable. The ✕ is now a duplicated, lower-discoverability path.
4
Director after — drop ✕ + retake 14px 20px padding. Stop / Clear / History stay (mode-specific verbs the tab bar doesn't carry). The 12px 20px today felt cramped vs Edit's 16/24 and Scheduler's 24/32; 14/20 splits the difference and is now uniform across all three. The "Clear conversation" label can sit on one line (no two-line wrap) once the ✕ is gone.
5
Scheduler before — transparent over page. The panel never wraps itself in --color-bg-surface; it inherits whatever's behind. Result: visually reads as a page-level view that got dropped into a panel slot, breaking the "this is a panel" register Edit + Director establish.
6
Scheduler before — centered with maxWidth: 980. Made sense when Scheduler was a routed sub-page reachable from anywhere; obsolete after mode-as-URL made it a peer panel in the same slot as Edit + Director. Today produces wasted side margins inside the right slot and makes the queue + jobs columns narrower than they need to be.
7
Scheduler after — header band + bg-surface + 18px title + meta-row. Drops the 22px h1 to match Edit's panel register. Meta line ("No active Brief · 0 queued · 50 agent jobs") moves into the header's meta row alongside an idle pip; same shape Director uses (pip + secondary text). Container loses its maxWidth; the section labels + card-lists fill the slot.
8
Scheduler after — section labels survive. "ACTIVE BRIEF" / "QUEUED BRIEFS" / "AGENT JOBS" at 10px uppercase letter-spacing .35em keeps the grouped-list vocabulary. Edit and Director don't acquire these — neither has grouped-list content to label.

#2 — Verdigris exactly 12 places. Unchanged. Nothing added. #4 — Panel typeface boundary. All three panel chromes stay on Inter. The prose surface inside Edit's Content tab is Lora per ProseEditor (unchanged). Director's agent reply bodies are Inter per v2.5 (the v2.4 Lora experiment was walked back). No transitions added.

Open Decisions for review
OQ-1 · Header padding value
D2 picks 14px 20px as the compromise between Edit's current 16/24, Director's 12/20, Scheduler's 24/32. The alternative is 16px 24px across the board (Edit's current value), which is slightly more generous. Both are defensible; the difference is visible mainly in the meta row's breathing room.
Recommendation: 14px 20px — splits the difference and reads as panel-tight rather than page-loose.
OQ-2 · Edit TabStrip border-top after header gains border-bottom
If Edit's header band gains a bottom border AND TabStrip keeps its own bottom border, the area between them is empty-and-double-bordered. Two options: (a) keep TabStrip's bottom-border + draw the header bottom-border directly above it (visually like a band of two parallel lines, which is the current state on Director); (b) drop the header's bottom border specifically for Edit because TabStrip carries it.
Recommendation: (a) — single-rule consistency wins. The "two parallel lines" appearance is invisible at 1px each on dark surface; it reads as one boundary.
OQ-3 · Director "Clear conversation" label
Today the button reads as "Clear / conversation" on two lines because of the ✕'s adjacent width. With the ✕ gone, it fits on one line. Keep as "Clear conversation" or shorten to "Clear"?
Recommendation: keep "Clear conversation" — "Clear" alone is ambiguous (clear what — the prompt input? the history? all the workflows?).
OQ-4 · Director document-name chip
The chip ("Shadow…") next to the DIRECTOR label currently echoes which document the conversation is for. The author is already on the document page; ModeTabBar shows the document mode tabs; the chip arguably duplicates context. Drop the chip (cleaner) or keep it (defends against a future "global Director" V2)?
Recommendation: keep — it reads as Director persona context, not navigation, and the V2 "Director across documents" backlog item per Director Architecture v2.6 §16.3 reuses exactly this affordance.
OQ-5 · Scheduler "Scheduler" title — what does it gain from a brand mark?
Edit has a node-title (real content). Director has a brand mark + Cinzel wordmark (persona). Scheduler just has the literal word "Scheduler". Could it earn a small mark — e.g. a clock glyph or "⌗" — to balance the visual weight against Director's mark?
Recommendation: no. Scheduler is an inspection panel, not a persona. A glyph would read as decorative noise, not signal. The 18px Inter title + meta line is correct for what Scheduler is.
OQ-6 · Shared <PanelHeader> primitive — now or after?
A React component <PanelHeader title meta actions /> would lock the convention in code so a future fourth mode can't drift. But it requires touching three call sites simultaneously and increases the diff. Now (one larger diff, harder to revert) or after (small restyle-in-place first, primitive in a follow-up commit).
Recommendation: after. D1–D6 first as a focused polish — small, all-defensive, all in the same direction. <PanelHeader> as a follow-up once the shape is stable.
