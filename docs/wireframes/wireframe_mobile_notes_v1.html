Will sync when online
Offline sync behaviour
Online:
Note uploaded immediately via POST /api/mobile/nodes/{id}/notes

Offline:
Note saved to local SQLite (mobile_sync_queue). Timestamp recorded as phone's local time.

On reconnect:
Queue drains via POST /api/mobile/sync. Sent in timestamp order. Server appends to JSONB array atomically.

No conflicts possible:
Append-only — notes are never edited or deleted from the phone. The JSONB array only grows.

Mobile API — Note Write PathTech Arch §15.2 · Product Spec §21.5
EndpointMethodBody / Response
/api/mobile/nodes/{id}/notesPOSTBody: { content, device_type, input_method, created_at }. Response: { note: { id, content, created_at, device_type, input_method } }
/api/mobile/syncPOSTBody: { notes: [{ node_id, content, created_at, device_type, input_method }] }. Sorted by created_at before appending. Response: { synced: number }
Atomic JSONB append: UPDATE nodes SET mobile_notes = mobile_notes || '[{...}]'::jsonb WHERE id = $1. PostgreSQL ensures atomicity — no race conditions between concurrent appends.
JSONB Data StructureProduct Spec §8.1 · Tech Arch §15.2
FieldTypeNotes
idstring (UUID)Generated server-side on write. Deduplication key for batch sync.
