05 — Annotations
1
Stop button — destructive token, NOT verdigris
Component Spec §5.14 baseline (V1.x-B.2) · §17.9 refinement (this wireframe)
Shipped in V1.x-B.2 as a single-action button in the DirectorPanel header. Uses destructive token (red border + red text), NOT verdigris — Inviolable #2 unchanged. V1.x-D refinement = add the confirmation modal + the three-way follow-on after stop. Button itself stays the same.
2
Confirmation modal — required before Stop fires
Component Spec §17.9 · Director Arch v2.3 §10 honesty principle
Pre-V1.x-D the Stop button fired immediately on click. V1.x-D adds a small confirmation step because Stop has real side-effects: it halts an in-flight LLM call (wastes any tokens already spent on the current step) and pauses subsequent steps. The modal makes those side-effects visible so the author can decide deliberately, not reflexively.
3
Side-effect honesty block
Component Spec §17.9 · Director Arch v2.3 §10 · simplified 2026-05-17
The blue-bordered block makes two honesty statements: (1) what's already done and will be kept (proportional, not numerical — "N of M steps complete"); (2) reassurance that state preserves on Stop. Brand voice rule: direct, complete, no alarm. No token or credit savings number — per user direction 2026-05-17, quantification of savings doesn't change the user's stop decision (proportion does), conflicts with the platform-credits vs BYOK-tokens unit split, and gives false precision against a rough estimate. Dollar values also not surfaced (provider-neutral, same rationale as CostMeter). Consumption detail lives in CostMeter — every other surface defers there.
4
Stopped banner — orange left border
Component Spec §17.9 · attention-amber convention
Persists in the conversation thread until the author makes a follow-on choice. Left border uses --st-rev (attention-amber) — same convention as in-review status badges. No verdigris — Stop isn't a positive completion; it's a paused state awaiting author decision. Banner stays in-thread (not floating overlay) so the conversation history reflects what happened.
5
Three-way follow-on · Resume / Cancel / View
Component Spec §17.9 · Director Arch v2.3 §10
Three distinct affordances rather than a single "OK what next" dialog: Resume (continues from persisted state; runs step N from scratch on re-entry); Cancel (destructive token — abandons remaining steps but keeps completed work); View what was done (read-only browse of the 4 completed outputs before committing to a Resume or Cancel decision). The author can View first, then come back and choose. The Cancel card uses destructive border to signal irreversibility. The Resume affordance uses a small green triangle as a "go" glyph — not verdigris fill, just a glyph colour cue.
6
Single-step Stop variant
§04 Variant A · Component Spec §17.9 honesty per turn-shape
When the running turn has only one step (typical for a quick refine), the honesty block shortens to a single-step statement. No "N of M complete" line because there's nothing to keep — "0 of 1" with a one-liner about resume re-running from scratch. The three-way follow-on after stop collapses: Resume + Cancel only (no View — nothing to view).
7
No-completed-work Stop variant
§04 Variant B · semantic alignment with Cancel
When Stop fires before any step has completed, the modal copy acknowledges that this is effectively a Cancel — there's no "keep" half. Open question: in this case, should the button label change from "Stop" to "Cancel" to be honest about what's happening? Or stay "Stop" with the explanatory subtitle? Recommendation: stay "Stop" — the user pressed Stop, they expect their press to do what it says; the subtitle handles the disambiguation.
06 — Inviolable audit & open decisions
Inviolable #2 audit · no new verdigris

The Stop refinement introduces no new verdigris uses. Stop button + Cancel card stay on destructive token (red). Resume affordance uses a small green triangle as a glyph — a 1-character colour cue, not a fill — and the affordance card background stays neutral --surface. The honesty block's left border uses --info (informational neutral). The stopped banner's left border uses --st-rev (attention-amber). Verdigris-use count remains nine.

Modal primary action uses the neutral btn-primary (white-on-black) — no verdigris because Stop is destructive, not affirmative. Inviolable #2 use #7 (affirmative-action triggers) does not apply.

Open decisions before build
  1. Numerical savings line. SETTLED 2026-05-17 — dropped. The proportional "N of M complete" line is sufficient signal; a token/credit number creates a unit problem (credits for platform, tokens for BYOK), gives false precision against a rough estimate, and competes with CostMeter (the dedicated consumption surface). The qualitative statement carries the decision-relevant content.
  2. Resume re-runs step N from scratch. The persisted state preserves at iteration boundary, so step N restarts. Acceptable? Recommendation: yes for V1; partial-step resume (continue from mid-LLM-call) is complex and rare. V2 candidate if users ask.
  3. View affordance. Drawn as a separate card. Alternative: just expand the PlanCard inline since it already shows completed-step outputs. Recommendation: keep separate — explicit "View what was done" is clearer than expecting the author to know they can scroll through PlanCard.
  4. Stop button while NOT running. What if the user clicks Stop after the turn already completed (race condition)? Recommendation: button greys out + becomes inert when the turn finishes; if a stale press fires, the modal explains "Director already finished. Nothing to stop." No-op exit.
  5. Stop on a queued (not running) workflow step. Different from Stop on a live Director turn. Open: same modal or different? Recommendation: the SchedulerPanel already exposes Cancel per row; Stop is reserved for the live turn surface. The Stop button in the Director header only appears when an active director_turn exists.
