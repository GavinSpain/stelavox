05 — Annotations
1
Stage membership indicator (optional)
Component Spec §17.8 · §A user-pref to hide
Compact "stage N" pill on nodes that belong to a Brief Stage. Uses a thin border + --surface background to stay quiet — many nodes will carry one and they shouldn't dominate the row. Optional: a user preference (tree.show_stage_membership) can hide them globally. Click routes to the stage detail in BriefViewer (§17.2 + concurrent-Brief wireframe).
2
AI-changed flag · attention without alarm
Component Spec §17.8 · §10 (failure UX) explicitly NOT this
Small dot in --info (blue-teal). Indicates AI has changed this node's content since the author last opened it. Cleared on next view of the node (selected → cleared). No verdigris — this is attention not affirmation. No attention-amber either — this isn't a failure/warning, it's positive information ("there's something new"). Tooltip: "AI changed this scene; open to review".
3
Lifecycle status badges · new V1.x-D states
Component Spec §17.8 · §4.4 NodeStatusBadge extension · TA v2.6 agent_jobs.status
Four new states extend the existing draft / in-review / approved / agent-complete badge set: scheduled, queued, executing, completed-pending-review. Each uses a neutral or informational token — none use verdigris (only approved + agent-complete are verdigris uses #4/#5). Lifecycle order: scheduled → queued → executing → completed-pending-review on an AI-driven path; transitions to approved/agent-complete on author commit.
4
Executing badge + AgentActivityIndicator co-existence
Component Spec §17.8 + existing AgentActivityIndicator §4.5
During execution both the RUN badge and the existing pulsing dot indicator render. They're complementary — the badge declares state at-a-glance scan; the dot is the live "heartbeat" feedback. Visual stacking: [stage] [auto-lock] [RUN] [●pulse]. The pulse uses --ag-run (blue) — established convention from B.2.1.
5
"Completed pending review" — interim state before author Approve
Component Spec §17.8 · §17.11 Director completion acknowledgement
When an agent_job completes successfully, the node enters completed-pending-review (NEW badge in --st-rev) and the AI-changed dot raises. This is the post-completion-pre-author-approve state — the author has not yet seen or approved the result. Important: this state is distinct from the existing agent-complete badge (verdigris use #4). agent-complete is the post-approve state; this NEW state is pre-approve. Avoids visual conflation between "AI is done" and "author is done".
6
Lifecycle progression A → F · narrative
§03 timeline
Reads left-to-right, top-to-bottom: (A) workflow approved, agent_job created; (B) waiting on WFQ throttle; (C) agent running; (D) job completed, author hasn't looked; (E) author opens the node, attention dot clears, NEW persists until manual approve; (F) author approves, transitions to agent-complete (verdigris use #4). Important: the NEW badge does NOT auto-clear on view — clearing requires an explicit author action ("Approve" or moving to a different status). This forces an intentional acknowledgement on AI-generated content.
7
AI-changed dot vs NEW badge — overlapping signals
Component Spec §17.8 · disambiguation
The two new V1.x-D signals are independent: AI-changed dot = "AI changed this; you haven't looked yet" (cleared on next view). NEW badge = "post-AI, pre-approve" (cleared on explicit author action). Common case: both fire after a successful agent_job, then the dot clears on view, the badge stays until approve. This is intentional — viewing-but-not-approving keeps the surface honest about author commitment.
8
User lock — existing pattern preserved
Component Spec §4.4 · existing V1 behaviour
Author-initiated lock unchanged: 🔒 in --text-s, hover tooltip names the locker + date. Descendants of a locked subtree inherit the lock visually (50% opacity glyph). User-locked subtrees refuse agent_job dispatch (existing M-008 + scheduler rule).
9
Auto-lock — V1.x-D new pattern
Component Spec §17.8 · TA v2.6 scheduled/queued/executing scheduler state
System-initiated lock from the scheduler. Visual: same 🔒 glyph but coloured in --info (distinct blue-teal) with a small ◷ clock overlay in the bottom-right corner. Released automatically when the holding agent_job transitions to a terminal state (completed / cancelled / failed). Hover tooltip names the upcoming or running work + ETA when known. Important: an author CAN override an auto-lock manually (e.g. cancel the scheduled job from SchedulerPanel) — auto-lock is not adversarial, it's protective.
06 — Inviolable audit & open decisions
Inviolable #2 audit · verdigris use count after V1.x-D NodeRow extensions

The four new V1.x-D badges (scheduled / queued / executing / completed-pending-review) and the AI-changed dot + auto-lock introduce zero new verdigris uses. All states are passive or informational; verdigris stays reserved for affirmative-action triggers (#7) and the two passive status uses already in place (agent-complete #4 + approved #5). Verdigris-use count remains nine.

Token choices:

  • --info (new neutral teal) for AI-changed dot and auto-lock — chosen so the new attention-without-alarm signal doesn't conflict with the attention-amber (--st-rev) used for failures or with verdigris (positive state). If --info doesn't exist in tokens.css yet, V1.x-D adds it.
  • --ag-run for executing-state pulse — existing convention from B.2.1.
  • --st-rev for completed-pending-review badge — attention-amber matches the convention for "needs your action" without escalating to destructive.
  • Neutral surface tones for scheduled / queued — these are operational states the author doesn't have to act on.
Open decisions before build
  1. Stage membership default-on or default-off? Drawn as on. Long-form authors may find it noisy. Recommendation: default-on with a single global toggle in /settings/tree; advanced users can hide. Alternative: default-off until Director starts using Stages routinely.
  2. AI-changed dot clear-on-view vs explicit-dismiss. Drawn as clear-on-view (read receipt model). Alternative: explicit "Mark seen" so the author can deliberately leave it "unread" while they investigate other nodes. Recommendation: clear-on-view — matches GitHub-style notification dot, lowest friction.
  3. NEW badge auto-clear on approve action vs persistence. Drawn as cleared only on explicit author Approve. Alternative: clear after N hours of last-viewed. Recommendation: explicit action only — forces intentional commitment to AI-generated content (matches Inviolable §1 author-origin discipline).
  4. Auto-lock override behaviour. User can cancel the holding agent_job (releases lock) but can't manually override the lock while the job runs. Drawn this way. Alternative: allow author to force-unlock + cancel in one action. Recommendation: keep two-step — accidental force-unlocks would orphan in-flight work.
  5. Multiple Stage memberships on one node. A node might belong to multiple active Briefs' Stages in V1.x-B.3 concurrent-Brief world. Drawn as a single "stage N" pill. Open: show stacked pills, or show count "+2 stages"? Recommendation: count if > 1 with hover for breakdown. Wireframe for concurrent-Brief surfaces (separate v1xd file) covers this case.
