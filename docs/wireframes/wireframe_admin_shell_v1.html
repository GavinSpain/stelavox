Admin Shell · v1.0 · 2026-06-14
What this covers. Admin becomes a self-contained operational interface with its own chrome — no AppShell project/node panels, no app navigation, no Dashboard back-link. One entry point (/admin), a left-rail nav to move between the three sections, and Admin's own auth gate. Achieved by lifting the routes out of the (app) group into a new (admin) group with its own layout.tsx + AdminShell. Inter only; no verdigris — status-green is --color-success.

Annotations
1AdminShell, not AppShell. A new app/(admin)/layout.tsx renders this shell instead of the app's three-panel AppShell. The admin routes move from app/(app)/admin/* to app/(admin)/admin/* — URLs stay /admin, /admin/payments, /admin/orchestration (route groups are invisible in the path).
2Left-rail nav. The three sections — Operations · Payments · Orchestration. Active item: --color-bg-selected fill + a neutral --color-text-secondary left border (not verdigris). This is the internal navigation; no app nav, no Dashboard link.
3Sign out only. Foot of the rail shows the admin's email + a Sign out button. No "return to app" affordance, per the brief — Admin is a separate operational interface.
4Per-section controls stay. The Operations window selector (1h/24h/7d) and the Payments tabs continue to live inside each section's content — the rail is top-level nav only.
5Pages unchanged. The existing Operations Summary, dashboard sections, Payments, and Orchestration render in the content area exactly as today. This is a chrome change only — no page logic touched.
Decisions — locked at the 2026-06-14 design discussion
Self-contained Admin.Locked Own route group + layout; no AppShell, no app nav integration.
Left-rail navigation.Locked Scales as Operations later splits into sub-views. Three items: Operations / Payments / Orchestration.
One entry point.Locked /admin; the rail handles the rest.
Sign out only, no Dashboard back-link.Locked Operators don't navigate back into the authoring app from the admin chrome.
Auth in the layout.Locked (admin)/layout.tsx gates on logged-in + isPlatformAdmin (redirect to /login otherwise). No trial-expiry / past-due gating — those are author concerns.
